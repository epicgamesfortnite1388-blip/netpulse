# Feature Audit — NetPulse Desktop (v0.2.0)

**Date:** 2026-09-12 · **Method:** every feature traced UI → API → backend service → native op → storage → visualization, then probed live against the **installed** packaged `.exe` in two layers:

1. **HTTP layer** — authed probes against the installed sidecar bundle (deploy battery).
2. **Webview layer (new)** — Chrome DevTools Protocol attached to the *live packaged webview* (`--remote-debugging-port`), verifying what the React app itself sends and renders: request URLs, response statuses, rendered measurements, and the absence of the backend-unreachable banner.

Layer 2 exists because this audit's headline bug was **invisible to layer 1**: the backend answered every curl/node probe perfectly while the packaged webview could not reach it at all. "Working" now means **both layers pass**, not merely that a screen exists.

## Desktop connectivity — root causes found & fixed (2026-09-12)

The reported "whole backend to frontend is broken / Backend unreachable (attempt 1095)" symptom had
**three stacked root causes**, each invisible to HTTP probes and unit tests:

| # | Root cause | Why invisible to tests | Fix | Verified |
|---|---|---|---|---|
| 1 | **CORS allowlist lacked the packaged webview origin.** UI is served from `http(s)://tauri.localhost`; the sidecar allowed only dev origins (`localhost:5173`). Every authed request (Bearer header) triggers a preflight the sidecar answered without `Access-Control-Allow-Origin`, so the browser blocked every response. | curl/Node don't enforce CORS; dev mode is same-origin via the Vite proxy | `DESKTOP_WEBVIEW_ORIGINS` merged into the default allowlist in `apps/api/src/config.ts`; `apps/api/test/desktopCors.test.ts` locks the contract (5 tests) | CDP: authed in-webview fetch went `Failed to fetch` → `200` |
| 2 | **`__TAURI__.invoke` does not exist in Tauri v2's `withGlobalTauri` bundle** — it lives at `__TAURI__.core.invoke`. Six modules checked only the top level, got `null`, and the app **silently fell back to same-origin web transport** — requests went to `tauri.localhost` itself (the SPA static handler), never to the sidecar. Net effect seen via CDP: **zero** sockets from webview to a healthy sidecar. | Dev mode runs on a real Vite server where the same-origin fallback *works* | Single robust resolver `tauriInvoke()` in `apps/web/src/lib/transport.ts` (checks `__TAURI_INTERNALS__` → `__TAURI__.core.invoke` → top level); all 6 call sites converted | CDP: `transport ready: http://127.0.0.1:<port>/api/v1`; OS netstat shows established webview→sidecar sockets |
| 3 | **Bootstrap `api_base` lacked the `/api/v1` prefix.** Web mode's `apiBase` is `/api/v1` and `api.ts` appends bare resource paths; the Rust bootstrap returned the bare origin, so even after fixes 1–2 every request 404'd. (`ws_base` was fine because `ws.ts` hardcodes `/api/v1/ws`.) | The route-wiring meta-test compares path *registrations*, not resolved URLs | `src-tauri/src/main.rs` bootstrap now returns `http://127.0.0.1:<port>/api/v1` (contract documented at both ends) | CDP: all app requests `200` (`/meta/health`, `/vpn/status`, `/map/local`, `/events`, `/network/status`) |

**Post-fix in-webview evidence (installed exe, PID-verified session):** 16–25 app requests observed, **all 200**; `hasBanner: false`; dashboard renders real `ms`/IP values; 4 persistent established webview→sidecar sockets; sidecar boots through `config→db→schedulers→routes` in ~1 s.

**Also fixed this pass (watchdog/recovery hardening, previously mid-flight):** watchdog no longer dies permanently on a poisoned mutex; sidecar death reason (decoded exit code + stderr tail) surfaces in the reconnecting banner; single authoritative log-dir resolver (System Health reads the same file the app writes); teardown reordered to stop the sidecar before event-loop destruction (tao `cannot move state from Destroyed` panic); startup sweep of orphaned WebView2 roots; signing moved strictly post-build (`beforeBundleCommand` signature was invalidated by Tauri's post-patch — the tampered-looking signature was prime antivirus bait).
