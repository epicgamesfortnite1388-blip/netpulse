### 2c. NetPulse API support

`tcpQuery` now accepts an optional HTTP CONNECT proxy, and `WhitednsService`
reads `WHITEDNS_PROXY`. When UDP is forged, it falls back to TCP/53 through
the proxy and labels the stage. `soar-check` has no proxy mode, so the
service skips the tunnel stage rather than claiming a false pass. A real
tunnel test still requires a proxy-capable client (as above).

## 3. What this changed in the code

- `DnsResponse` now exposes the `AA` bit.
- `WhitednsService` requires `AA=1` and NS/SOA for the **exact** zone over
  UDP; the live parent-SOA shape is accepted but labeled non-conforming. An
  empty forged answer no longer passes.
- TCP/53 is checked with a real length-prefixed DNS query (`tcpQuery`), not a
  TCP connect.
- `tcpQuery` can use an HTTP CONNECT proxy; `WHITEDNS_PROXY` makes the service
  fall back to TCP/53 through the local proxy when UDP is forged.
- `WHITEDNS_PUBKEY` is used when the UI omits the public key.
- `WHITEDNS_SOAR_CHECK` selects the diagnostic path; if absent, the tunnel
  stage is skipped, never marked as passed.
- Regression tests: 16/16 in `whitednsService.test.ts`; full API suite
  97 files / 1055 tests; API typecheck, lint, and build exit 0.

## 4. Reproduce safely

1. Use the VPS or another non-TUN host for DNS-path tests.
2. Do not disable the user's TUN/proxy without consent.
3. Do not print the public key, panel path, or profile.
4. Run `-tcp off`, `-tcp only`, and `-tcp auto`; all three must pass before
   claiming both DNS transports.
5. Run a wrong-key control; it must fail.
6. Repeat at least 20 times before a reliability claim.
