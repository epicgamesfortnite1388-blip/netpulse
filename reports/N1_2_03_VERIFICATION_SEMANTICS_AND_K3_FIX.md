# N1_2_03 — Verification Semantics and K-3 Fix

**Phase:** N1.2 · **Commits:** `c7fe33b` (three-way), `d46ece9` (pure mapping + tests)

## The semantic mapping, now a single tested function

The explanation is generated by
`InvestigationManager::verify_result_text(top, confidence, verified, failure_reproduced)`
(investigation.rs) — a pure function unit-tested over all cases. The
lifecycle calls it; the frontend displays the backend's string verbatim (the
`result` field of the status snapshot — the UI computes nothing).

### Case A — predicted failure reproduced
`"...{hyp} reproduced on re-measurement (confidence X%); the re-measurement
supports this hypothesis, though it does not by itself prove the complete
root cause."`
- Says the failure was reproduced and that the measurement SUPPORTS the
  hypothesis. Explicitly does not claim proof of the complete causal story.
- Never uses "unverified"/"not verified".

### Case B — predicted failure not reproduced
`"...{hyp} not reproduced on re-measurement (confidence X%); the observation
challenges this hypothesis and the posterior was updated accordingly — treat
the verdict as uncertain."`
- The observation contradicts the leader; the posterior update is
  acknowledged; the verdict is explicitly uncertain (the leader may survive
  on flaky-fault posteriors — stated, not hidden).

### Case C — verification unavailable
`"...{hyp} could not be verified (the implicated layer was not re-measured);
absence of verification is not success — treat the verdict as uncertain."`
- Reached when no API failed the implicated layer, the registry entry is
  gone, or cancellation hits. Missing measurement is never success; no
  fabricated verification result exists (the `verified` boolean is computed
  only from a real re-measured layer).

### Case D — inconclusive
With boolean layer outcomes (`Ok` / `Failed` / `Unknown`) there is no fourth
measurable outcome; a measurement that cannot discriminate competing
hypotheses contributes only through its posterior weight. D therefore shares
B's explicit-uncertainty wording while the posterior carries the nuance —
documented as a deliberate modeling fact, not silently collapsed. The
principled upgrade (IG-guided verification via the existing `rank_tests`)
remains an N5/roadmap item, noted in N1_REVIEW_01 §5.

### Floor precedence (tested)
Whatever the re-measurement showed, a posterior below the established 0.25
conclusion floor yields the preserved refusal — asserted for all three
outcome combinations. The exactly-0.25 boundary is a justified conclusion
(strict less-than) — asserted and documented.

- The `verified` boolean and the `VerificationCompleted` event schema are
  unchanged (N0/N1.1 contracts) — only the human-readable string mapping was
  corrected and centralized.

  string; no frontend-side verification truth exists.
